# CanvaStage Sync Spike — guided test

This is a **temporary development-only companion app**. It runs inside the Canva **editor** and tells CanvaStage which editor page is selected.

It does not watch Canva's full-screen Present mode, capture browser traffic, or send slide text, images, Canva credentials, or OAuth tokens. It sends only:

- Canva design ID
- Canva page ID
- A temporary, eight-character pairing code generated by CanvaStage

The companion reads a short-lived Canva design token only inside Canva to identify the design. That token never leaves the Canva iframe and is not sent or logged.

> **Important:** this companion is separate from the Canva OAuth integration already configured in CanvaStage. In the Canva Developer Portal, use **Your apps**, not **Your integrations**.

## What you need

- The CanvaStage spike build running on the **same Windows computer** as the browser.
- Google Chrome. Canva currently recommends browser preview for local apps; the Canva desktop app requires additional HTTPS certificate setup.
- Node.js 24 and npm 11. Check with `node --version` and `npm --version`.
- A Canva account that owns or can edit the presentation you will test.

Do not use a phone or another computer for this test. `localhost` means this specific Windows computer.

## Part 1 — start the two local programs

### 1. Start the CanvaStage listener

1. Open **CanvaStage**.
2. Select **Setup & diagnostics** in the left navigation.
3. In **Canva page-sync spike**, click **Start local listener**.
4. Leave CanvaStage open and copy or note the eight-character **Pairing code**.
5. If you have not done so since installing this spike build, return to **Presentation**, select the presentation, and click **Apply** once. This stores Canva's page IDs in the local CanvaStage cache.

### 2. Keep the companion server running

Open **Windows Terminal** or PowerShell. Change to this folder inside the downloaded CanvaStage source checkout:

```powershell
cd path\to\CanvaStage\spikes\canva-stage-sync
```

For example, if you cloned the repository to your Documents folder:

```powershell
cd "$HOME\Documents\CanvaStage\spikes\canva-stage-sync"
```

Then run:

```powershell
npm install
npm start
```

Leave that terminal window open. A message that the development server is running at `http://localhost:8080` means this step worked. Opening that address directly in a browser will not show a normal app page; Canva loads it into its own editor frame.

## Part 2 — create a draft Canva app

This creates a private-in-practice **draft** for testing. It is not published to the Canva Apps Marketplace unless you later submit and release it.

1. In Chrome, open the [Canva Developer Portal](https://www.canva.com/developers/).
2. Select **Your apps**. Do **not** select **Your integrations**.
3. Click **Create an app**.
4. Give it a clear temporary name, such as `CanvaStage Sync Spike`.
5. If Canva asks who the app is for, choose **Public** unless your Canva team is on an Enterprise plan and you specifically want a team app. Choosing Public here does not make a draft visible to other Canva users.
6. Accept the developer terms and click **Create**.

Leave the app in Draft status. Do not use **Submit app** or **Release** for this spike.

## Part 3 — point Canva at the local companion

1. In the new app's Developer Portal page, open **Code upload**.
2. Find **App source** and choose **Development URL**.
3. Enter exactly:

   ```text
   http://localhost:8080
   ```

4. Save the change if Canva shows a Save button.
5. Open the app's **Scopes** page. Enable **Design read** (`canva:design:content:read`) and leave all other scopes disabled. This is the only permission declared by the companion's `canva-app.json` file.
6. If the portal offers an **Intents** setting, ensure **Design Editor** is enabled. This is the editor side-panel intent used by the companion.

The Development URL field exists only for local development. Canva will not allow an app to be submitted while that field has a value, which is expected for this test.

## Part 4 — preview and install the companion

1. Return to the app's main page in the Developer Portal.
2. Click **Preview** (usually near the upper-right of the page). If Canva asks for an intent, choose **Design Editor**.
3. Canva opens a new browser tab containing a Canva editor with the app in a side panel.
4. The first time only, click **Open** to install/connect the draft app.
5. Chrome may display a **local network access** prompt in the address bar. Click **Allow**. This permission lets the Canva iframe reach the CanvaStage listener at `127.0.0.1` on this computer.
6. The panel should display **CanvaStage Sync Spike**. Enter the pairing code from CanvaStage and click **Start watching page**.

If the panel says CanvaStage cannot be reached, confirm that CanvaStage's listener is running and grant Chrome local-network access. If you previously denied it, click Chrome's blocked permission icon in the address bar and turn local-network access on.

## Part 5 — test against the intended presentation

The page that CanvaStage selected and the page the companion reads must belong to the **same Canva presentation**.

1. In Chrome, open the presentation you applied in CanvaStage. Open it in **Edit design** mode, not Present mode.
2. Open the draft companion from Canva's **Apps** area. After the first Preview/installation, draft apps can be opened from the editor's Apps area for the account that created them. Look for the name you chose, `CanvaStage Sync Spike`.
3. Enter the pairing code again if needed and click **Start watching page**.
4. Click different page thumbnails in the Canva editor.
5. Within roughly one second, CanvaStage should change its manually selected confidence page and display a status such as `Synced to Canva page 8`.

The Developer Portal's **Preview** button is useful to confirm that the companion loads, but it may open a new preview design. If CanvaStage reports that the update is from a different design, open the same real presentation in the Canva editor and launch the draft app from its Apps area before trying again.

## What a successful result means

Success proves that a Canva Apps SDK companion can read the selected page in the Canva **editor** and communicate that selection directly to CanvaStage over a loopback-only connection.

It does **not** prove that it can see page changes during Canva's full-screen **Present** mode. After editor testing succeeds, start Present mode and observe whether the companion continues to receive changes. Report the result either way; that answer determines whether this approach can become a production feature.

## If something does not match these steps

- **No Development URL field:** make sure you are in the companion app under **Your apps** > _your app_ > **Code upload**, not the OAuth integration under **Your integrations**.
- **Preview does not load:** verify `npm start` is still running and the Development URL is exactly `http://localhost:8080`.
- **Chrome blocks access or the panel reports `127.0.0.1:17334`:** these are two different local addresses. `localhost:8080` is the companion's development server; `127.0.0.1:17334` is CanvaStage's receiver. Keep both CanvaStage and `npm start` running, then allow Chrome local-network access from the address-bar permission prompt. This permission is remembered only for the current Chrome session.
- **The companion says the page has no stable ID:** use a regular Canva presentation, not a Doc or Whiteboard.
- **CanvaStage says “different Canva design”:** the app is open on a different Canva design than the one selected in CanvaStage. Open the correct presentation in Edit design mode and retry.
- **CanvaStage says it cannot match the page:** click **Apply** for that presentation in CanvaStage again, then restart watching.
- **The presentation is in full-screen Present mode:** this is an intentionally unanswered part of the spike. The companion may not remain available there.
