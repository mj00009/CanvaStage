# CanvaStage Sync Spike

This is a development-only Canva companion app used to test whether the selected page in the Canva editor can drive CanvaStage automatically.

It sends only these values to a loopback listener on the same Windows computer:

- Canva design ID
- Canva page ID
- A temporary, eight-character pairing code generated by CanvaStage

It does not send slide text, page images, Canva credentials, OAuth tokens, or browser traffic.
The companion reads a short-lived Canva design token only inside the Canva iframe to obtain its design ID; that token never leaves the iframe or appears in a request or log.

## Prerequisites

- A Windows test computer with the CanvaStage spike build running.
- Google Chrome and a Canva account that can create a draft developer app.
- Node.js 24 and npm 11, as required by Canva's current Apps SDK tooling.

## Test procedure

1. In CanvaStage, open **Setup & diagnostics** and start **Canva page-sync spike**. Note the pairing code.
2. In this directory, run `npm install` and then `npm start`. Keep that terminal running; Canva serves the app from `http://localhost:8080`.
3. In the Canva Developer Portal, create a draft app, set its **Development URL** to `http://localhost:8080`, and enable the `canva:design:content:read` permission from `canva-app.json`.
4. Preview the app in a Canva presentation editor. If Chrome asks to allow local network access, allow it for this test.
5. Open the companion app in Canva's side panel, enter the CanvaStage pairing code, and choose **Start watching page**.
6. Apply the same presentation in CanvaStage once after installing this spike. That refresh records Canva page IDs in the local cache.
7. Select different pages in the Canva editor. CanvaStage should select the corresponding confidence page within roughly one second.

## What this proves

Success proves that Canva's editor page metadata can reach the local desktop app with no cloud relay. It does **not** prove that the companion can observe changes while Canva is in full-screen Present mode. Test that workflow separately before treating this as a production solution.

## Deliberate limitations

- The listener binds only to `127.0.0.1` and stops when CanvaStage closes.
- The pairing code changes every time the listener starts.
- This is a development bridge, not a production authentication or hosted relay design.
- Canva team apps require a Canva Enterprise team. A draft developer app is sufficient for this spike.
