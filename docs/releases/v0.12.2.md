# CanvaStage v0.12.2

This release adds a remembered-display reconnect prompt for [#43](https://github.com/mj00009/CanvaStage/issues/43) and clearer display-loss guidance and logs for [#44](https://github.com/mj00009/CanvaStage/issues/44).

## Changes

- When the remembered Extended display returns, CanvaStage can offer to start output using the current cached deck, without repeating Setup or downloading it again. The prompt names the display and defaults to No.
- Declining keeps output off. Repeated display notifications do not repeat the offer for the same connection. An explicit Stop suppresses later offers until the operator requests output again.
- Missing, ambiguous, unknown, or Primary targets are not offered. After Yes, CanvaStage checks that the target, cached deck, and output intent have not changed while the prompt was open. It preserves the current page, mode, layout, and tracking state; output starts unblanked.
- The disconnect warning explains that Windows no longer reports the selected screen, identifies the warning as CanvaStage's, and gives recovery steps. Logs distinguish a display-loss safety stop from an operator Stop.
- Automated screenshot fixtures use basic, neutral sample text. The help guide includes Full and Compact view instructions and screenshots.

The #44 log shows Windows removing the cast TV before CanvaStage stopped output. The cause of that wireless disconnect remains unconfirmed. This release does not claim to fix casting, change Presenter polling, or add transitions. #41 and #42 are not included.

## Download and test

Download `CanvaStage-v0.12.2-win-x64.zip`, extract the entire ZIP into a new folder, and run `CanvaStage.Windows.exe` using the same Windows account. Saved credentials, cached content, appearance, and display preferences carry over. The package remains unsigned, portable, and self-contained for Windows 11 x64, with Apache-2.0 `LICENSE` and `TRADEMARKS.md`.

1. Load your intended deck, reconnect its remembered screen using Extend, and check the named display in the Yes/No prompt. No should keep output off; Yes should start the current page without a new download.
2. Stop output manually and reconnect again. Output should stay off without a reconnect offer. Use Start output or Start setup when ready.
3. If the screen disconnects while the prompt is open, answering Yes must not send output to another monitor.
4. Compare the Chrome/casting disconnect with a wired HDMI connection. Record whether Windows still lists the TV and whether other apps can use it. Keep #44 open while the cause is being investigated.

Help and F1 open the matching public guide. See [display reconnect notes](../development/display-reconnect.md) for implementation and acceptance details.
