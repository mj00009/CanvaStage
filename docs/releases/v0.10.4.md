# CanvaStage v0.10.4

This maintenance release restores the separate output window's previous text fitter and adds diagnostics for [#24 — Confidence Mode Freezes](https://github.com/mj00009/CanvaStage/issues/24). It remains an unsigned, self-contained Windows 11 x64 portable package.

## Changes

- Restores only the separate Preview/display window's v0.10.2 deferred text-fitting path. The v0.10.3 in-app preview fitter and matching Current/Next font family/default weight are retained. The separate window may briefly show oversized text before shrinking it; this is an accepted temporary tradeoff.
- Adds privacy-safe logs for Presenter observations, selected pages, output snapshots, queued revisions and one-shot render-stage callbacks. Logs record binding matches, character counts, font sizes, viewport and DPI, not slide text or credentials.
- Adds output placement, display-change and WPF rendering-capability telemetry. These observations do not reset graphics, change rendering mode or control the display connection.
- Standardizes new log entry and embedded diagnostic timestamps to ISO 8601 UTC with a `Z` suffix. Older appended entries are not rewritten. Operator-facing clock/status times remain local, with local status text labeled in diagnostic summaries.
- Adds synthetic Windows verification of output drawing changes across 40 Presenter pages, backward jumps and pause/manual/resume transitions, without forced layout/fitting/redraw before inspecting the drawing pixels. Adds UTC timestamp unit tests and wireless-display acceptance guidance.

No functional changes were made to Presenter tracking, Canva exports, refresh scheduling, installers or signing.

## What is not confirmed

The real-machine freeze has not been reproduced or proven to originate in the text fitter. The operator used Windows wireless casting to a Samsung TV; one blank-output event persisted across a CanvaStage restart and recovered after disconnecting/reconnecting the display. The mouse was visible, but unrelated applications were not tested. The rollback is a precaution, not proof of the cause or a guaranteed wireless-display fix.

Synthetic drawing-pixel verification checks WPF output, not physical screen pixels or wireless delivery. Issue #24 stays open pending testing on the affected computer and receiver.

## Install or upgrade

1. Close CanvaStage.
2. Download `CanvaStage-win-x64.zip` and extract the complete ZIP into a new folder.
3. Run `CanvaStage.Windows.exe` using the same Windows account. Existing preferences, cached content and protected Canva setup are reused; do not clear cache or disconnect to upgrade.

The ZIP includes the Apache-2.0 license and trademark notice. Windows may show an unsigned-app warning.

## Please test

The local cross-build passes without warnings, and all 63 Core unit tests pass. Windows build, tests and published runtime/UI verification passed for both [main](https://github.com/mj00009/CanvaStage/actions/runs/37158270337) and the [release tag](https://github.com/mj00009/CanvaStage/actions/runs/37158454234), including the new 40-page output drawing test. Representative generated output/operator screenshots were reviewed. Real-Canva and wireless-display acceptance remain user checks.

- Navigate at least 40 Presenter pages, forward and backward, with an unchanged deck. Compare page/status, in-app preview, separate Preview and TV output.
- Pause/resume tracking and try manual Previous/Next. All output surfaces should continue updating.
- Try long text, large font sizes, layouts, the clock and Current/Next typography. The separate window can briefly resize text, but should settle without clipping.
- If output freezes or goes blank, export diagnostics before recovery where possible. Record whether the mouse is visible, whether Notepad displays on the TV, and whether restarting CanvaStage or reconnecting the wireless display restores content.

Test before relying on this version during a service. See the [Windows acceptance guide](../windows-acceptance.md).
