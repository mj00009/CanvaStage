# CanvaStage v0.6.0 acceptance guide

## Before a service

1. Extract the full Windows release ZIP and open CanvaStage using the usual Windows operator account. Administrator elevation is not required.
2. In Presentation, verify **Saved securely** appears under Client Secret. Do not replace a saved secret merely because its characters are hidden. If configuring for the first time, enter the credentials, Save configuration, then Connect Canva.
3. Apply the presentation. Reapply it after editing the Canva deck. Hidden slides are excluded from local visible-page numbering after export; the PPTX download itself still includes them.
4. Close extra Canva Presenter windows, then open the Presenter View used for the service. **Following Canva** in Live control means its current page counter is accepted.
5. Open Preview, select the confidence display, and start output. Confirm the output changes when you navigate in Presenter View.
6. Try manual previous/next in CanvaStage. It must say **Paused — manual control** and stay on that page as Canva changes. Choose Resume sync to return to the current Canva page.

## Real Windows acceptance checklist

These require a real Canva account and actual Windows display settings. CI does not substitute for these checks.

- [ ] Supported browser and Canva desktop app: record the versions that were tested. Confirm Presenter counters and identity availability; do not assume every provider exposes a document URL.
- [ ] Navigate forward, backward, and jump to distant pages. Normal detection should occur within about two seconds, depending on accessibility scan duration; report slower updates.
- [ ] Keep one Canva Presenter View open. If multiple Presenter windows are open, CanvaStage follows the first counter exposed by Windows; close unused Presenter windows before the service.
- [ ] Open a deck with a different visible-page count. CanvaStage must report a presentation mismatch and hold the last valid page.
- [ ] Close Presenter View. Output must hold the last page. Reopen Presenter View and confirm automatic following resumes without restarting CanvaStage.
- [ ] Disable automatic sync and restart; it must remain disabled. Temporary Pause does not persist across restart.
- [ ] Test Windows scaling at 100%, 125%, 150%, and 200%, including moving the operator window between monitors with different scaling. The title bar must remain reachable.
- [ ] Test all Monitor layouts, maximum font size, long text, image fallback, and Mirror. Check clipping, readability, and style updates in Preview and output.
- [ ] Reapply the same deck while its image is displayed. The refresh must finish without a file-in-use error. Close and reopen and confirm cached pages and saved connection remain usable.
- [ ] Unplug/reconfigure the confidence display and confirm safe output handling and available operator controls.

## Automated verification

The release workflow builds and tests the app, then launches the published self-contained executable with `--ui-demo-screenshot=...` and `--ui-verification-directory=...`. It uses synthetic data in isolated temporary storage. It never loads the operator's cached deck or saved credentials in this mode.

The `ui-demo-preview` artifact contains screenshots and `verification/verification.json`. The workflow fails if functional checks, output text-fit checks, core text contrast, or WPF binding checks fail. The generated images still require visual review.

The scaling checks render at different raster DPI and effective window sizes. They are simulations, not automated changes to Windows system DPI. Hardware hotplug, mixed-DPI window placement, live Canva changes, and accessibility-provider hangs require real-machine tests.

## Known boundaries

- This release reads accessibility data; it has no screen-capture/image-matching fallback.
- CanvaStage follows the first Presenter page counter exposed by Windows. It validates the visible-page total but does not identify the deck from its window title or URL, so only one Presenter View should be open.
- A stalled external accessibility provider can delay scanning; retries handle exceptions, not a permanently blocked Windows API call.
- Each successful refresh has its own image-cache folder. Previous generations remain on disk; cleanup controls are not included yet.
- Disconnect removes protected credentials intentionally. Merely closing the application does not remove them. Use the same Windows account to reuse DPAPI-protected credentials.
